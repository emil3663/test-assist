### TA-238 — Test Assist isn't registered as an installed app on Windows

- **Phase:** 3
- **Priority:** P3
- **Suggested labels:** `packaging`, `windows`
- **Problem it solves:** Test Assist ships as an unzipped, portable folder
  with no Start Menu entry, no "Add or Remove Programs" listing, and no
  Windows App Paths registration. Surfaced concretely during today's pass:
  a remote computer-use session tried to resolve "Test Assist" (and
  "TestAssist") as a controllable application and got "not installed" for
  both — the permission layer that drives apps on a user's behalf only
  recognizes apps Windows itself knows about, and a bare exe in a folder
  isn't one of them. The same gap affects anything else that discovers apps
  the same way: Start Menu search, "Open with" suggestions, third-party
  automation or scripting tools, screen readers that key off registered
  app metadata.

  This is adjacent to but distinct from the existing file-association
  ticket (`TESTASSIST_BACKLOG.md`, registry-write-for-"Open with" item) —
  that one is about Test Assist *opening files*; this is about Windows
  knowing Test Assist *exists* as an application at all, independent of any
  file type.
- **Scope:**
  - Decide how far to go: a minimal per-user Start Menu shortcut (no admin
    rights, consistent with "installs by unzipping") versus a full
    installer (MSIX or similar). The existing file-association ticket
    already sets the precedent of user-scoped registration only, never
    system-wide/admin, for an app that installs by unzipping — follow the
    same constraint here.
  - If a Start Menu shortcut is the chosen scope: create it on first run or
    via a small setup step, pointing at the current install location, and
    keep it correct across in-place updates (this is also where a stale
    shortcut pointing at an old build, as happened earlier today, would
    stop being possible).
- **Deliverables:** A recorded decision on scope; if implemented, the
  registration step and a manual test case in `DESKTOP_TEST_PLAN.md` (real
  Windows shell state, not something the automated suite can verify).
- **Acceptance criteria:** Test Assist is discoverable as an installed
  application by standard Windows mechanisms (Start Menu search at
  minimum) without the user manually creating a shortcut.
- **Dependencies:** None blocking. Worth sequencing near the existing
  file-association ticket since both touch how Test Assist presents itself
  to Windows.
