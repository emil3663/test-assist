### TA-234 — No file name is shown anywhere after opening an existing saved file

- **Phase:** 3
- **Priority:** P2
- **Suggested labels:** `bug`, `ux`
- **Problem it solves:** Opening a previously saved file gives the user no way
  to tell, from the app itself, which file is currently open — no file name
  appears in the title bar, the window, or anywhere in the editor chrome.
  Reported directly in today's Block A findings; not display- or DPI-related,
  so it reproduces regardless of monitor configuration.
- **Scope:** Establish where the currently-open file's identity should be
  surfaced (window title is the conventional place) and confirm it updates on
  open, save-as, and rename; confirm behaviour for the "no file open /
  unsaved" state so that case reads clearly too.
- **Deliverables:** The file name displayed somewhere persistent in the UI
  while a file is open, correct across open/save/save-as/close.
- **Acceptance criteria:** Opening any existing file makes its name visible in
  the app without requiring File > Open or an OS-level file dialog to check.
- **Dependencies:** None.
